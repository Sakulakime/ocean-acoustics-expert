# v0.2.0 - Topic-driven multi-book retrieval

The expert now chooses its primary textbook by topic and proactively checks other relevant books for complex questions. Previously, COA was the default and other books were mainly consulted when COA notes could not answer the question.

## What's new

- A shared book-selection policy covers COA, Collins & Siegmann, Colosi, Etter, and Brekhovskikh & Lysanov. Method comparisons, validity questions, environmental uncertainty/coherence, and research or validation recommendations trigger relevant cross-book checks.
- Four substantive topic notes were built from targeted reads of the original books: PE rational approximations, starters and range-dependent interfaces; stochastic regimes and acoustic coherence; model evaluation and prediction uncertainty; and waveguide and rough-surface approximation limits.
- A source note's section map is now explicitly navigation rather than sufficient technical evidence. The retrieval record distinguishes `checked-note`, `checked-pdf`, unavailable evidence and checks that are not needed.
- Routes now include model evaluation, frequency coherence, adiabatic validity, small-slope scattering and additional PE/mode-transport windows. Mode-transport windows are split by statistic rather than treated as one large reading range.
- OpenCode keeps its PDF-reading restriction while using substantive topic notes for cross-book checks and reporting any evidence it cannot obtain.
- The Codex usage guide distinguishes loading the router skill from spawning the expert role, and explains that automatic delegation depends on the session configuration.

## Validation

- 218 automated tests pass; the shared selection-policy regression covers all four generated harness artifacts and the router.
- 67 route-selection cases, knowledge-base integrity checks and MATLAB helper checks pass.
- Local link-mode installation was refreshed for Codex, Claude Code, OpenCode and DeepSeek-TUI. `doctor` passes and a repeat installation dry run is a no-op.
- A fresh Codex CLI session completed the full spawn-and-return answer probe with the installed read-only expert, choosing Etter as primary and COA for a substantive cross-check. Its answer distinguished note-based citations from original PDF reads. The smoke invocation used `gpt-6.1-sol`; user model defaults were not changed. The other harnesses received installation/configuration checks and automated adapter coverage, rather than live model-answer probes.
- Package inspection includes the selection policy and four topic notes, and excludes book PDFs and local work files.
- Independent source spot-checks found no material equation or validity-condition errors in the selected high-risk claims. This is a targeted source review, not a numerical propagation validation.

## Install this release

```sh
npx --yes ocean-acoustics-expert@0.2.0 install
```

The matching [npm package](https://www.npmjs.com/package/ocean-acoustics-expert/v/0.2.0) is published and `latest` points to `0.2.0`. Future published GitHub Releases synchronize their matching package versions through the repository's `publish-npm.yml` workflow using npm Trusted Publishing (OIDC). Stable releases use `latest`; prereleases use `next`. See [release publishing](https://github.com/Sakulakime/ocean-acoustics-expert/blob/main/docs/releasing.md) for checks and retries. Reinstall to refresh generated agent and router files, then confirm a fresh session sees the updated descriptions.

Book PDFs remain user-supplied under `knowledge/sources/`. Missing books do not prevent note-based answers; the expert reports any required page-range reading it could not complete.

The new notes cover their stated sections, not complete books. No acoustic solver, numerical-convergence study, frequency-generalization experiment or native Windows test was run for this release.
